# TechCorp Game - Java Spring Boot API - Final Project Java

A management simulation game API built with **Java Spring Boot** and deployed on **Render**.

## 1. Project Overview

TechCorp Game is a backend API for a business management simulation game where players manage employees, projects, and company resources. The application demonstrates key software engineering concepts including:

- RESTful API design with Spring Boot
- Layered architecture pattern (API, Domain, Engine, Exceptions, Constants)
- Maven-based build automation
- Docker containerization with multi-stage builds
- Cloud deployment on Render platform
- Custom exception handling
- Object-oriented design principles

## 2. Features

- **Game State Management** - Track turn-based game progress and player statistics
- **Employee Management** - Create and manage different employee types (Developer, Manager, Tester)
- **Project Management** - Assign employees to projects with budgets and deadlines
- **AI Opposition** - AI player competes against human player with strategic decisions
- **Financial System** - Track cash, budget allocation, and expenses
- **Exception Handling** - Custom exception hierarchy for robust error management
- **Health Check Endpoint** - Service availability monitoring and status checks
- **Production-Grade Logging** - SLF4J logging framework with INFO, DEBUG, WARN, ERROR levels
- **Input Validation** - Comprehensive parameter validation for all methods
- **Kubernetes Health Probes** - Liveness, readiness, and startup probes for container orchestration
- **Structured JSON Responses** - All endpoints return consistent JSON format with status, message, timestamp
- **Game Constants Validation** - 62 configurable constants with static initialization validation
- **Custom Exception Hierarchy** - 3 exception classes with error codes and severity levels
- **Resource Management** - Proper Scanner/connection cleanup with try-finally blocks

## 10. Game Classes

### 10.1 Domain Models

#### Company.java
- Manages company financial state (cash, reputation)
- Tracks employees and projects
- Calculates company score: Cash + (Reputation × 10)
- Methods: addCash(), addReputation(), hireEmployee(), addProject()

#### Employee.java (Abstract Base Class)
- Base class for all employee types (Developer, Manager, Tester)
- Properties: name, salary, skill (1-100), experience level
- Implements Comparable<Employee> interface
- Abstract method: getProductivity()
- Methods: increaseSkill(), addExperience(), getContribution()

#### Developer.java
- Subclass of Employee
- Productivity multiplier: 1.2x (highest)
- Properties: codeQualityLevel (0-100), programmingLanguages[]
- Salary multiplier: 5000.0, Max salary: 500,000
- Quality bonus: codeQualityLevel / 100 × 0.3

#### Manager.java
- Subclass of Employee
- Productivity multiplier: 0.8x (team coordination)
- Properties: motivationLevel, delegationSkill, managedTeam[]
- Salary multiplier: 7000.0, Max salary: 700,000
- Team efficiency bonus: 0.5-1.5x based on motivation & delegation

#### Tester.java
- Subclass of Employee
- Productivity multiplier: 0.9x (QA focus)
- Properties: bugFindingRate (1-100), testCoverageLevel (0.0-1.0)
- Salary multiplier: 3000.0 (lowest cost), Max salary: 300,000
- QA bonus: (coverage × 0.1) + (bugFinding × 0.05), capped at 0.12

#### Project.java
- Properties: name, status, difficulty, deadline, assignedEmployees[]
- Status enum: NOT_STARTED, IN_PROGRESS, COMPLETED, FAILED, CANCELLED
- Difficulty enum: EASY (90% success), MEDIUM (75%), HARD (60%), CRITICAL (40%)
- Methods: startProject(), completeProject(), failProject(), calculateTeamQuality()

### 10.2 Game Logic

#### GameEngine.java
- Core game engine managing all game flow
- Properties: playerCompany, aiCompany, totalRounds, currentRound
- Handles Scanner input and user validation
- Methods:
  - runGame() - Main game loop with exception handling
  - playRound() - Execute single round
  - processPlayerChoice() - Handle player input (1: Assign Project, 2: Pause, 3: Skip)
  - validateInput() - Validate player input (1-3)
  - displayGameResults() - Show final scores and winner
- Exception handling: InsufficientFundsException, InvalidProjectException, NoSuchElementException
- Logging: INFO, DEBUG, WARN, ERROR levels

#### AIPlayer.java
- Static utility class for AI opponent logic
- Strategy enum: AGGRESSIVE, BALANCED, DEFENSIVE
- Methods:
  - takeTurn() - Execute AI turn with strategic decision
  - analyzeGameState() - Determine strategy based on cash ratio
  - executeStrategy() - Implement chosen strategy
  - startHighValueProject() - Risky high-reward projects
  - startMediumProject() - Balanced approach
  - startSafeProject() - Conservative low-risk projects
  - hireRandomEmployee() - Dynamic workforce management
- AI Decision Thresholds:
  - AGGRESSIVE_THRESHOLD: 0.7 (70% cash available)
  - DEFENSIVE_THRESHOLD: 0.3 (30% cash available)
  - MIN_CASH_BUFFER: 10,000

### 10.3 Exception Handling

#### GameException.java (Base Class)
- Properties: errorCode, severity, timestamp, componentName, recoveryAction
- Severity enum: LOW (1), MEDIUM (2), HIGH (3), CRITICAL (4)
- Methods: isCritical(), isHighSeverity(), getErrorReport(), logError()

#### InsufficientFundsException
- Error code: FUNDS_001
- Severity: MEDIUM
- Properties: amountNeeded, amountAvailable, operationName
- Methods: getShortageAmount(), getShortagePercentage(), canBeCoveredBy()

#### InvalidProjectException
- Error code: PROJECT_001
- Severity: HIGH
- Properties: projectName, projectStatus, validationFailureReason, requiredTeamQuality, actualTeamQuality
- Methods: getQualityDeficit(), getQualityDeficitPercentage(), canBeFixedWith()

### 10.4 Configuration

- 62 organized constants in 15 categories

- Validates all constants on class load

  - Salary multipliers: Developer=5000, Manager=7000, Tester=3000
  - Max salaries: Developer=500000, Manager=700000, Tester=300000
  - Productivity multipliers: Developer=1.2, Manager=0.8, Tester=0.9
  - Project success rates: EASY=90%, MEDIUM=75%, HARD=60%, CRITICAL=40%
  - Team management: MAX_TEAM_SIZE=20, MAX_COMPANY_SIZE=50
